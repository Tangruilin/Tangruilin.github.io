SSD时代下LSM与B+树的演进对比

本文字数： 1.4k 阅读时长 ≈ 5 分钟

背景

LevelDB 作为 LSM Tree 的经典实现，其设计初衷是针对 HDD 时代「随机写慢、顺序写快」的特点进行优化。但随着 SSD 的普及，存储硬件的特性发生了根本性变化，LSM Tree 的优势是否依然存在？本文从 LevelDB 的演进出发，分析 LSM Tree 和 B+ 树在 SSD 时代的优劣对比。

HDD 时代：LSM 的绝对优势

在机械硬盘时代，随机写和顺序写的性能差距巨大：

LSM Tree 的核心思想就是将随机写转换为顺序写：写入先入 MemTable（内存），再批量刷盘。这个设计在 HDD 上带来了巨大的性能优势。

相比之下，B+ 树的随机写（页分裂、节点更新）在 HDD 上性能惨淡。

SSD 时代：LSM 优势被削弱

SSD 改变了硬件特性：

随机写和顺序写的差距大幅缩小，LSM 的核心优势减弱。

更严重的是，LSM 的 Compaction 机制带来严重的写放大：

相比之下，B+ 树的写放大只有 2-3 倍（主要是页分裂开销）。

SSD 时代初步对比

维度 LSM B+ 树
写放大 高（10-50x） 低（2-3x）
随机写优势 减弱 不明显
读延迟 不稳定（Compaction 抖动） 稳定
SSD 寿命 不友好 相对友好

在 SSD 普及初期，LSM 整体逊色于 B+ 树。

范围查询：LSM 的软肋

Key-Value 分离并非万能，范围查询是其明显劣势：

场景 B+ 树聚簇索引 Key-Value 分离 LSM
范围查询 10 条 ~5 IO（顺序） ~10 IO（随机）
范围查询 100 条 ~8 IO（顺序） ~100 IO（随机）
范围查询 1000 条 ~15 IO（顺序） ~1000 IO（随机）

范围越大，差距越悬殊。这是 Key-Value 分离方案的核心代价。

总结

维度 B+ 树 LSM（传统） LSM（Key-Value 分离）
写放大 低（2-3x） 高（10-50x） 低（1-3x）
点查询 3-4 IO 1-多次 IO 1 IO（内存索引）
范围查询 快（聚簇索引） 中等 慢（随机 IO）
热点写入 有局部热点 均匀 均匀
SSD 寿命 中等 不友好 友好

结论：

  1. SSD 普及初期，LSM 因写放大问题整体逊色于 B+ 树
  2. Key-Value 分离让 LSM 重新获得竞争力：写放大降低、内存索引解决读取问题、追加写对 SSD 寿命友好
  3. 范围查询仍是 Key-Value 分离 LSM 的软肋，B+ 树聚簇索引在此场景下有明显优势

选型建议：

  • 点查询为主 + 写入密集 → Key-Value 分离 LSM
  • 范围查询为主 + 读密集 → B+ 树聚簇索引
  • 混合场景 → 根据实际负载测试选择

存储引擎的演进从未停止，LSM 和 B+ 树的边界也在逐渐模糊。理解各自优劣，才能在具体场景中做出正确选择。
